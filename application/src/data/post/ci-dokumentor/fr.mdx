> 📖 La documentation de vos pipelines CI/CD ne devrait jamais être obsolète. Elle devrait se générer automatiquement depuis vos fichiers de configuration.

Dans l'écosystème DevOps moderne, les pipelines CI/CD sont au cœur de la delivery. GitHub Actions, GitLab CI, Azure DevOps, CircleCI... chaque plateforme a son format, ses spécificités, ses conventions. Mais un problème reste universel : **comment maintenir une documentation à jour de vos composants CI/CD sans effort manuel ?**

Chez HoverKraft, nous avons développé **CI Dokumentor**, un générateur automatique de documentation pour vos actions GitHub, templates GitLab, ou tout autre composant CI/CD réutilisable. L'outil est open source, gratuit, et disponible en ligne de commande, Docker, GitHub Action, et même intégré dans Dagger.io.

📦 Le projet est disponible sur : [github.com/hoverkraft-tech/ci-dokumentor](https://github.com/hoverkraft-tech/ci-dokumentor)

## Pourquoi documenter automatiquement ses composants CI/CD ?

### Le problème : documentation désynchronisée

Dans un workflow classique, un développeur crée une GitHub Action réutilisable avec des `inputs`, `outputs`, et une logique métier complexe. Il rédige un README à la main, souvent incomplet, rarement mis à jour lors des évolutions ultérieures.

**Conséquence** : la documentation diverge du code. Les nouveaux arrivants ne comprennent pas les paramètres disponibles. Les équipes perdent du temps à lire le code source plutôt que de consulter une doc claire.

### La solution HoverKraft : Documentation-as-Code

CI Dokumentor analyse automatiquement vos fichiers `action.yml`, `template.yml` ou équivalents, et génère une documentation Markdown structurée contenant :

- La description complète du composant
- Les inputs avec types, valeurs par défaut, et descriptions
- Les outputs générés
- Des exemples d'utilisation concrets
- Les badges de versions et licences
- Un lien vers le dépôt GitHub

Cette documentation vit **dans le dépôt**, est **versionnée avec le code**, et se **régénère automatiquement** à chaque modification grâce à un pipeline CI/CD.

## Les cas d'usage concrets

### 1. Documentation de GitHub Actions

Vous maintenez une bibliothèque de GitHub Actions réutilisables (déploiement Terraform, scan de sécurité, notifications Slack...). Avec CI Dokumentor, chaque `action.yml` génère automatiquement son README.

**Avant** : 30 minutes pour rédiger manuellement un README incomplet.
**Après** : 10 secondes pour générer une doc complète et structurée.

### 2. Catalogue de templates GitLab CI

Votre organisation partage des templates GitLab CI (.gitlab-ci-template.yml) entre projets. CI Dokumentor génère un catalogue centralisé avec descriptions, paramètres, et exemples.

### 3. Composants réutilisables Dagger.io

Vous construisez des modules Dagger en Go ou TypeScript. CI Dokumentor documente automatiquement vos fonctions publiques en analysant les métadonnées.

### 4. Audit de conformité

Lors d'un audit de sécurité ou de conformité, vous devez prouver que chaque composant CI/CD est documenté. CI Dokumentor génère automatiquement les preuves.

## Guide rapide d'utilisation

### Installation en ligne de commande

```bash
# Installation globale via npm
npm install -g @ci-dokumentor/cli

# Génération de documentation
ci-dokumentor generate --source action.yml

# Ou directement avec npx sans installation
npx @ci-dokumentor/cli generate --source action.yml
```

### Utilisation avec Docker

Idéal pour intégrer CI Dokumentor dans un pipeline sans dépendance Node.js.

```bash
# Afficher les options disponibles
docker run --rm ghcr.io/hoverkraft-tech/ci-dokumentor/cli:latest --help

# Générer la documentation depuis un fichier local
docker run --rm \
  -v $(pwd):/workspace \
  -u $(id -u):$(id -g) \
  ghcr.io/hoverkraft-tech/ci-dokumentor/cli:latest \
  generate --source /workspace/action.yml
```

### Intégration GitHub Actions

Automatisez la génération de documentation à chaque push sur `main`.

```yaml
name: Generate Documentation

on:
  push:
    branches: [main]
    paths:
      - 'action.yml'
      - '.github/workflows/docs.yml'

jobs:
  generate-docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Generate CI Documentation
        uses: hoverkraft-tech/ci-dokumentor@c46a1a108957237cf485103a80b060c35c7dba33 # 0.2.2
        with:
          source: 'action.yml'

      - name: Commit documentation
        run: |
          git config user.name "GitHub Actions"
          git config user.email "actions@github.com"
          git add README.md
          git diff --quiet && git diff --staged --quiet || \
            git commit -m "docs: update auto-generated documentation"
          git push
```

### Intégration GitLab CI

```yaml
generate-docs:
  stage: docs
  image: ghcr.io/hoverkraft-tech/ci-dokumentor/cli:latest
  script:
    - ci-dokumentor generate --source templates/my-component/template.yml
  artifacts:
    paths:
      - templates/my-component/docs.md
  only:
    changes:
      - templates/**/*.yml
```

### Intégration Dagger.io

Pour les équipes utilisant Dagger pour leurs pipelines CI/CD.

```go
func (m *MyModule) GenerateDocs(
  ctx context.Context,
  source *dagger.Directory,
) *dagger.Directory {
  return dag.Container().
    From("ghcr.io/hoverkraft-tech/ci-dokumentor/cli:latest").
    WithMountedDirectory("/workspace", source).
    WithWorkdir("/workspace").
    WithExec([]string{
      "ci-dokumentor",
      "generate",
      "--source",
      "action.yml",
    }).
    Directory("docs")
}
```

## Cas d'usage avancés

### 1. Génération multi-formats

CI Dokumentor peut générer de la documentation dans différents formats :

- **Markdown** (par défaut) : pour GitHub, GitLab, BitBucket
- **HTML** : pour intégration dans un portail développeur (Backstage)
- **JSON** : pour indexation dans un moteur de recherche

### 2. Validation de qualité

Utilisez CI Dokumentor en mode **lint** pour valider que vos composants CI/CD sont bien documentés :

```bash
ci-dokumentor lint --source action.yml --strict
```

En mode strict, l'outil retourne une erreur si :

- Des inputs n'ont pas de description
- Des outputs manquent
- La description générale est absente ou trop courte

Intégrez ce check dans vos pull requests pour garantir la qualité.

### 3. Catalogue centralisé

Générez un catalogue de tous vos composants CI/CD en une commande :

```bash
# Scanner récursivement tous les fichiers action.yml
find . -name "action.yml" -exec ci-dokumentor generate --source {} \;

# Générer un index centralisé
ci-dokumentor catalog --output docs/catalog.md
```

Ce catalogue peut être publié dans votre portail développeur (Backstage, Portainer) pour centraliser la découverte.
